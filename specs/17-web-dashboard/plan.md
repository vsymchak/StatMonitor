# Технічний план реалізації SPEC-17: Веб-дашборд

## 1. Архітектура компонентів

```
                          ┌────────────────────────────┐
                          │   Supabase (PostgreSQL)    │
                          │   - paper_bets             │
                          │   - ai_match_analysis      │
                          │   - scheduler_plan         │
                          │   - system_heartbeat       │
                          └─────────────┬──────────────┘
                                        │ (psycopg2 / pandas)
                                        ▼
┌──────────────────────────────────────────────────────────────────────────┐
│                             dashboard.py                                 │
│  - load_kpi_metrics()      -> Підрахунок балансу, ROI, вінрейту          │
│  - load_bets_data()        -> Отримання активних та закритих ставок      │
│  - load_ai_verdicts()      -> Завантаження вердиктів Gemini              │
│  - load_scheduler_state()  -> Отримання розкладу та пульсу               │
│  - render_ui()             -> 3 вкладки: Ставки, AI-аналітика, Здоров'я  │
└──────────────────────────────────────────────────────────────────────────┘
```

---

## 2. Залежності проекту
Створюється файл `requirements.txt`:
```text
streamlit>=1.30.0
psycopg2-binary>=2.9.9
requests>=2.31.0
matplotlib>=3.8.0
pandas>=2.1.0
plotly>=5.18.0
```

---

## 3. Обробка стану відсутності з'єднання (Offline/Fallback resilience)
Якщо `SUPABASE_DB_URL` не задано (наприклад, при першому відкритті на локальній машині без `.env`), дашборд:
* Надає поле для вводу URL бази даних у боковій панелі (Sidebar Settings).
* Або завантажує репрезентативні демо-дані для перевірки інтерфейсу.
